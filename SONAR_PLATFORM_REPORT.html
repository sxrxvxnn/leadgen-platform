Section 01

Platform Overview

Sonar is a full-stack B2B lead intelligence platform that helps go-to-market teams discover, enrich, and engage high-fit prospects. It combines a LinkedIn data extraction browser extension, an AI-powered enrichment backend, an Excel-grade spreadsheet UI, and automated outreach sequences into a single unified product.

What it does

Users install the Sonar Chrome Extension and browse LinkedIn. The extension captures company and contact profiles in one click, syncing them to the Sonar dashboard. The backend enriches each record automatically — pulling funding rounds, tech stack, emails, and social signals — and scores leads against the user's ICP (Ideal Customer Profile). AI models generate personalised LinkedIn DMs and email sequences. A feature-flagged admin panel lets the team manage users, feature access, and announcements.

Core Value Proposition Find the right companies, enrich them in seconds, reach out with personalised messages — all without leaving the platform.

Data flow

1. Capture: The Chrome Extension injects a content script into LinkedIn profile, company, and search pages. When the user clicks "Save to Sonar", the extension POSTs raw LinkedIn data directly to the backend API at leadgenengineplatform-api.vercel.app, authenticated with the user's JWT from Supabase.

2. Store: The backend validates and stores the lead or company record in Supabase (PostgreSQL). Each record is tenant-scoped by user_id, ensuring complete data isolation between users.

3. Enrich: On-demand or via cron, the enrichment pipeline fills in missing data: employee count via PDL, emails via Hunter/proprietary scraper, tech stack via website analysis, funding via web scraping, and social signals via GitHub/HackerNews scrapers.

4. Score & Surface: The React dashboard fetches enriched data, scores leads against the user's ICP, and renders them in a spreadsheet view, kanban pipeline, or card layout with filters, sort, and export.

5. Engage: Users compose personalised LinkedIn DMs and email sequences powered by LLMs. Email opens/clicks are tracked via pixel and redirect links. Sequences with warm-up scheduling are managed server-side.

Security & Compliance

Authentication

  • Supabase JWT — RS256 signed, verified server-side
  • Password policy: 8+ chars, upper, lower, digit
  • Password reset via email OTP (Supabase)
  • OAuth callback via onAuthStateChange (no manual code exchange)
  • Profile auto-created on first OAuth login

API Security

  • SlowAPI rate limiting (token bucket per user/IP)
  • Path-based sliding-window limiter (custom middleware)
  • Request body size limit: 2 MB max
  • CORS: explicit allowlist of origins
  • Docs (Swagger/ReDoc) disabled in production

HTTP Security Headers

  • X-Content-Type-Options: nosniff
  • X-Frame-Options: DENY
  • Content-Security-Policy: default-src 'none'
  • Strict-Transport-Security (prod only, 2yr preload)
  • Referrer-Policy: strict-origin-when-cross-origin
  • Permissions-Policy: no camera/mic/geo/payment

Data Isolation

  • Row-level security (RLS) in Supabase
  • Every table user_id-scoped
  • Admin routes check is_admin flag in profile
  • Audit log: all sensitive actions recorded
  • Sentry: error monitoring with PII scrubbing
  • PostHog: product analytics (no PII in events)

Section A · Security

Authentication & JWT Validation

SOCEngineering

Every protected API route begins by calling get_user_id(authorization). This extracts the Bearer token from the HTTP header, verifies it against Supabase Auth (RS256), and returns the user's UUID. Any invalid or expired token raises HTTP 401 immediately — no logic runs before this check.

backend/app/routes.py · lines 203–214Python
def get_user_id(authorization: str) -> str:
    try:
        token = authorization.replace("Bearer ", "").strip()
        if not token:
            raise ValueError("Missing token")
        user = supabase_auth.auth.get_user(token)
        return user.user.id        # Supabase verifies RS256 signature here
    except Exception:
        raise HTTPException(status_code=401, detail="Invalid or expired token")
SOC — what to know
  • Token verification is delegated to Supabase Auth — the backend never decodes JWT manually, so there is no risk of algorithm-confusion attacks (e.g. RS256 → HS256 downgrade)
  • A single point of entry: every protected route uses this same helper — no routes bypass it
  • On failure the error message is generic ("Invalid or expired token") — no leakage of internal state
  • Login endpoint is rate-limited to 5 req/min per IP to prevent brute-force credential attacks

Login — email verification + anti-enumeration

backend/app/routes.py · login routePython
@router.post("/auth/login")
@limiter.limit("5/minute")                   # brute-force guard
async def login(request: Request, user: UserLogin):
    try:
        response = supabase_auth.auth.sign_in_with_password({...})
    except Exception:
        log_auth_failure(email=user.email, ip=_ip(request), reason="invalid_credentials")
        raise HTTPException(status_code=401, detail="Invalid email or password")

    # Block unverified emails from accessing the platform
    if not response.user.email_confirmed_at:
        log_auth_failure(..., reason="email_not_verified")
        raise HTTPException(status_code=403, detail="Email not verified...")

    log_auth_success(user_id=response.user.id, ip=_ip(request))
    return {"access_token": ..., "refresh_token": ...}
SOC — key controls
  • Rate limit: 5 attempts/minute per IP — excessive failures trigger log_auth_failure events visible in logs
  • Email enumeration prevention: both "wrong password" and "email not found" return the same 401 with identical message
  • Unverified email addresses receive HTTP 403 — they cannot receive a token even if the password is correct
  • All login events (success and failure) are emitted as structured JSON log events for SIEM ingestion
Signup — anti-enumeration The signup endpoint always returns: "If this email is not already registered, you will receive a confirmation link shortly." — regardless of whether the email already exists. This prevents attackers from enumerating registered accounts.
Section B · Security

Rate Limiting — Global + Per-Path

SOC

Two independent rate-limiting layers protect the API. SlowAPI handles per-route decorators. A custom sliding-window middleware enforces per-IP limits by path category — with tighter limits on expensive AI and paid-API endpoints.

backend/app/security.py · path rate limit configPython
# Most-specific match wins — checked in order
_PATH_LIMITS: list[tuple[str, int]] = [
    # Bulk AI calls — tightest limit (expensive + slow)
    ("/bulk-autofill",    4),    # 4 req/60s per IP
    ("/bulk-analyze",     4),
    ("/bulk-maps-enrich", 4),
    # Single AI calls
    ("/analyze-website",  10),
    ("/check-compliance", 10),
    ("/autofill-linkedin",10),
    ("/autofill",          20),
    # Paid enrichment APIs
    ("/maps-discover",    15),
    ("/people-search",    20),
    ("/enrich",           40),
    # Global fallback
    ("",                  200),   # 200 req/60s per IP
]
SOC — design rationale
  • Bulk AI endpoints are limited to 4/min — prevents a single compromised account from triggering $100s of Groq or Firecrawl charges
  • Paid enrichment endpoints (PDL people-search, ProxyCurl) are capped at 15–20/min — protects credit budgets from abuse
  • The sliding window is in-process (per Vercel function instance); for strict multi-instance enforcement, Redis-backed SlowAPI should be used at scale
  • Rate limit hits emit security.rate_limit log events with IP and path — filterable in any log aggregator
backend/app/security.py · sliding-window middlewarePython
async def path_rate_limit_middleware(request: Request, call_next):
    path = request.url.path
    if path in _SKIP_PATHS:               # /health, /docs, etc. — bypass
        return await call_next(request)

    ip  = request.client.host or "0.0.0.0"
    lim = _path_limit(path)
    key = f"{lim}:{ip}"
    now = time.monotonic()

    bucket = _buckets[key]
    # Evict timestamps older than the 60s window
    while bucket and now - bucket[0] > _WINDOW_SECS:
        bucket.popleft()

    if len(bucket) >= lim:
        log_rate_limit_hit(ip=ip, path=path, limit=lim)
        return JSONResponse(status_code=429, content={"detail": "Too many requests"})

    bucket.append(now)
    return await call_next(request)
Section C · Security

SSRF Protection

SOC

When the backend fetches user-supplied URLs (website analysis, company prefill), it first validates them through validate_external_url() — a full SSRF guard that blocks private IP ranges, loopback, link-local, cloud metadata endpoints, and DNS rebinding attacks.

backend/app/security.py · SSRF guardPython
# All private / reserved IP ranges are blocked
_PRIVATE_NETS = [
    ip_network("10.0.0.0/8"),
    ip_network("172.16.0.0/12"),
    ip_network("192.168.0.0/16"),
    ip_network("127.0.0.0/8"),
    ip_network("169.254.0.0/16"),   # AWS/Azure/DO metadata (169.254.169.254)
    ip_network("100.64.0.0/10"),    # Carrier-grade NAT
]

_BLOCKED_HOSTS = frozenset({
    "localhost", "127.0.0.1", "::1",
    "169.254.169.254",              # AWS/Azure/DO metadata
    "metadata.google.internal",     # GCP metadata
    "100.100.100.200",              # Alibaba Cloud metadata

def validate_external_url(url: str, field: str = "url") -> str:

    hostname = (parsed.hostname or "").lower()
    if hostname in _BLOCKED_HOSTS:
        log_suspicious("ssrf_blocked_host", ...)
        raise HTTPException(403, ...)

    # DNS resolution check — catches DNS rebinding attacks
    addrs = socket.getaddrinfo(hostname, None, ...)
    for _, _, _, _, sockaddr in addrs:
        if not _ip_is_safe(sockaddr[0]):
            log_suspicious("ssrf_blocked_resolved_ip", ...)
            raise HTTPException(403, ...)
SOC — threat model covered
  • Direct IP attacks: private/loopback IPs in the URL are rejected before any network call
  • DNS rebinding: all resolved IPs for the hostname are checked, not just the literal hostname — prevents attackers registering a public domain that resolves to 169.254.169.254
  • Cloud metadata exfil: all major cloud metadata endpoints (AWS, GCP, Azure, Alibaba) are explicitly blocked by hostname
  • Protocol restriction: only http/https allowed — blocks file://, ftp://, gopher:// vectors
  • All SSRF attempts emit security.suspicious log events with the target URL for forensics

All LLM inference in the platform is routed through a single _call_ai() function. It tries Groq → Gemini in order, emits a $ai_generation PostHog event with token counts and latency for every call, and raises HTTP 503 if no AI key is available.

backend/app/routes.py · _call_ai() · lines 4789–4850Python
def _call_ai(prompt: str, max_tokens: int = 300,
              user_id: str = None, feature: str = None) -> str:
    """Groq → Gemini in order. Emits $ai_generation to PostHog per call."""
    groq_key   = os.getenv("GROQ_API_KEY", "")
    gemini_key = os.getenv("GEMINI_API_KEY", "")
    content  = ""
    trace_id = str(uuid.uuid4())      # unique ID to correlate logs with PostHog

    if groq_key:
        t0 = time.monotonic()
        r = requests.post(
            "https://api.groq.com/openai/v1/chat/completions",
            headers={"Authorization": f"Bearer {groq_key}"},
            json={"model": "llama-3.3-70b-versatile",
                  "messages": [{"role": "user", "content": prompt}],
                  "max_tokens": max_tokens, "temperature": 0.2},
            timeout=20,
        )
        if "choices" in r.json():
            content = r.json()["choices"][0]["message"]["content"].strip()
            posthog.capture(user_id, "$ai_generation", {
                "$ai_provider":      "groq",
                "$ai_model":         "llama-3.3-70b-versatile",
                "$ai_input_tokens":  usage.get("prompt_tokens"),
                "$ai_output_tokens": usage.get("completion_tokens"),
                "$ai_latency":       round(time.monotonic() - t0, 3),
                "$ai_trace_id":      trace_id,
                "feature":           feature,   # e.g. "bulk_icp_score", "dm-generate"
            })

    if not content and gemini_key:
        # Gemini fallback — same pattern, different API shape
        r = requests.post(
            f"https://generativelanguage.googleapis.com/.../gemini-2.0-flash:generateContent?key={gemini_key}",
            json={"contents": [{"parts": [{"text": prompt}]}]}, timeout=20)
        # Parses candidates[0].content.parts[0].text ...

    if not content:
        raise HTTPException(503, "No AI key configured.")
    return content
AI Team — design notes
  • Single function = single place to add new providers (e.g. Anthropic, Mistral) — just add another fallback block
  • PostHog $ai_generation event captures input tokens, output tokens, latency, and a trace_id — allows per-feature cost analysis in the PostHog AI analytics dashboard
  • feature parameter identifies the calling context (e.g. "bulk_icp_score", "dm-generate") — use this to compare cost/latency per feature
  • Temperature is fixed at 0.2 for most calls — low enough for deterministic JSON output, high enough for natural prose in DMs
  • Groq is always tried first — it's free and faster (~200ms vs ~800ms for Gemini)

    return "SELECT * FROM person WHERE " + (" AND ".join(clauses) if clauses else "1=1")

// ── TTL Cache — 30 second window prevents duplicate GET requests ──
const _cache = new Map()
const CACHE_TTL = 30_000   // 30 seconds

function _cacheGet(key) {
  const entry = _cache.get(key)
  if (!entry) return null
  if (Date.now() - entry.ts > CACHE_TTL) { _cache.delete(key); return null }
  return entry.data
}
export function invalidateCache(...keys) {
  if (keys.length === 0) { _cache.clear(); return }
  for (const k of keys) _cache.delete(k)    // targeted invalidation after mutations
}

// ── Auto JWT refresh — handles 401 responses without log-out ──
let _refreshPromise = null   // lock prevents concurrent refresh calls

api.interceptors.response.use(
  (response) => response,
  async (error) => {
    const original = error.config
    if (error.response?.status === 401 && !original._retried) {
      original._retried = true
      if (!_refreshPromise) {
        // All concurrent 401s share ONE refresh call — prevents token refresh race
        _refreshPromise = api.post('/auth/refresh', { refresh_token: refreshToken })
          .finally(() => { _refreshPromise = null })
      }
      const res = await _refreshPromise
      localStorage.setItem('token', res.data.access_token)
      original.headers.Authorization = `Bearer ${res.data.access_token}`
      return api(original)   // retry original request with new token
    }
  }
)
Engineering — key design decisions
  • TTL cache: all GET requests are cached for 30 seconds — navigating between Companies and back doesn't re-fetch from the API
  • invalidateCache('/companies') is called explicitly after create/delete/bulk operations — ensures the UI shows fresh data immediately after mutations
  • Refresh promise lock: if 5 simultaneous requests all 401, they all await the same single refresh call — prevents 5 parallel token refresh requests which would cause a race condition
  • The retry path sets _retried = true — prevents infinite refresh loops if the refresh token itself is expired

  bp.Q.value = 1.4

  const gain = ctx.createGain()
  gain.gain.setValueAtTime(vol, ctx.currentTime)
  gain.gain.exponentialRampToValueAtTime(0.001, ctx.currentTime + 0.028)

  src.connect(bp) → bp.connect(gain) → gain.connect(ctx.destination)
}

// Clickable detection — catches React-handled divs, not just buttons
function isClickable(el) {
  if (CLICKABLE_TAGS.has(el.tagName?.toLowerCase())) return true
  if (window.getComputedStyle(el).cursor === 'pointer') return true
  return false
}
AI Team — Web Audio implementation
  • White noise burst + bandpass filter at 2.8–3.4kHz mimics the frequency signature of a mechanical keyswitch — frequencies below 1kHz (thud) and above 4kHz (hiss) are cut
  • Frequency is randomised ±300Hz per keypress — prevents the "canned sound" effect of identical repeating sounds
  • Exponential gain ramp to 0.001 (not 0) — browsers disallow ramp-to-zero; 0.001 is below the threshold of human hearing
  • AudioContext is lazily created on first user gesture — browsers block audio until a user interaction has occurred
  • Click detection via getComputedStyle(el).cursor === 'pointer' catches React onClick handlers on divs and spans that aren't native <button> elements
